Multi-Agent Systems · LangGraph · Software Reliability

Six agents take a production failure from raw signal to a verified repair plan.

SENTINEL is an architecture for autonomous software reliability. A Mission Controller dispatches specialist agents to analyse a failure, form and test hypotheses, isolate the root cause, and draft a repair — then an Adversarial Verification agent tries to tear the conclusion down before anyone trusts it. The engineering is in the brakes: no finding ships until it survives challenge.

The six agents

Each agent has one job, a bounded toolset, and a structured output contract. Specialisation is what makes the verification step meaningful — the agent checking the work is not the agent that produced it.

Architecture

SENTINEL is designed as a LangGraph state graph: shared state, conditional routing, and gates that can send work backwards as well as forwards.

  • State graph orchestration. Agents read and write a single typed state object (incident, evidence, hypotheses, verdicts), so every conclusion is traceable to the evidence that produced it.
  • Conditional routing. The Mission Controller dispatches based on failure class and confidence; low-confidence branches loop back for more evidence instead of guessing forward.
  • Verification gates. The Adversarial Verification agent runs regression thinking, edge cases, and output validation against every root-cause claim — a claim that fails challenge returns to the Hypothesis agent, not to production.
  • Human-in-the-loop. Cases below the confidence threshold escalate to an engineer with the full evidence trail attached. Automation handles the volume; humans keep the judgment calls.
  • Auditability by construction. Every agent action is logged against the incident state, producing the same kind of audit trail regulated production systems require.
